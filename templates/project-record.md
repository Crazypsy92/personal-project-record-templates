# 项目研发档案｜项目名称

> **定位：** 面向个人工程研发与科研实践的长期项目档案，记录项目从需求定义、技术设计、开发实施、问题排查、实验测试到成果交付的全过程。
>
> **核心原则：** 记录事实、保留证据、区分实现与验证、让项目可追溯和可恢复。
>
> **使用方式：** 不要求每天填写全部章节。日常只更新顶部快照、任务和研发日志；遇到问题、开展实验或调整方案时，再填写对应章节；阶段验收或结项时补充交付与复盘。
>
> **文件原则：** 一个项目优先维护这一份主档案。原始代码、日志、CSV、图片、视频和完整测试报告仍保留在项目目录中，本文件记录摘要、结论和相对路径。资料较多时可以另建文件，但应从本档案建立索引。
>
> **填写约定：** 不适用填写 `N/A`，暂不掌握填写 `待确认`；不要为了填满表格而编造数据。明确区分「已实现」「已执行」「已验证」「已交付」。

## 附：统一术语与状态口径

| 术语 | 含义 |
|---|---|
| 已实现 | 功能或方案已有具体实现，不代表通过验收 |
| 已执行 | 已按记录的条件实际运行，不代表结果合格 |
| 已验证 | 满足指定标准且有实际证据，注明验证环境及范围 |
| 已交付 | 约定交付物已形成并记录版本与位置 |
| 已冻结 | 当前暂不继续推进，需说明理由和恢复准入条件 |
| 假设 | 尚未用充分证据确认的解释或猜想 |
| 仿真验证 | 只对所用模型、参数、场景和运行版本负责 |
| 真机验证 | 实际硬件在记录的条件下运行并按标准验收 |
| N/A | 经确认不适用，并非尚未执行 |

**最终原则：** 记录是为了帮助未来的自己，而不是为了把表格填满。日常只写“目标—动作—结果—证据—下一步”；遇到关键难点、创新、实验或里程碑时，再展开对应章节。
