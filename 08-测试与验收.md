# 08 · 测试与验收总览

## 1. 三种不同记录

-   **测试用例（Case）：** 要测什么、怎么测、通过标准是什么。ID 稳定。
-   **执行批次（Run）：**
    某日期、某版本实际执行的一次测试。每次执行新增记录，不覆盖旧结果。
-   **验收结论（Acceptance）：** 某版本 /
    阶段是否满足预先定义的标准，必须有证据。

自动化测试 PASS 不代表 GUI 人工验收通过；仿真 PASS 不代表真机 PASS。

## 2. 状态定义

  状态           含义                               是否计入通过
  -------------- ---------------------------------- ------------------
  PASS           已执行，符合明确标准且证据可追溯   是
  FAIL           已执行但不符合标准                 否
  SKIP           本次按明确理由跳过                 否
  NOT RUN        本批次未执行                       否
  NOT VERIFIED   证据不足，无法确认                 否
  BLOCKED        被前置条件 / 环境阻塞              否
  N/A            确认不适用并说明理由               不纳入适用项分母

## 3. 五层验证范围

  ----------------------------------------------------------------------------------------------------------------------
  层级              典型内容                                 证据示例                       不能替代什么
  ----------------- ---------------------------------------- ------------------------------ ----------------------------
  单元测试          函数、类、算法边界、异常分支             pytest / unittest 报告         不能证明模块协作正常

  集成测试          模块接口、数据库、文件、设备适配         报告与日志                     不能证明 GUI 可用

  GUI 测试          页面、表单、导航、错误提示、关键流程     实际操作记录 / 截图 /          控件构建成功不等于桌面验收
                                                             自动化报告                     

  仿真验收          场景、轨迹、碰撞、接触、指标、停止条件   仿真日志、数据、图表           不能证明真机一致

  硬件 / 真机验收   实物通信、动作、保护、传感器、任务       设备日志、测量数据、人工确认   模拟或仿真不能替代
  ----------------------------------------------------------------------------------------------------------------------

不是所有项目都需要五层。明确不适用时记录 N/A
和理由，不要把未做的真机测试标成 PASS。

## 9. 发布 / 交付前检查

-   [ ] 测试范围和目标版本明确
-   [ ] 自动化原始报告已保存
-   [ ] 失败项已关联问题或解释
-   [ ] SKIP、NOT RUN、NOT VERIFIED、BLOCKED 分别列出
-   [ ] GUI 自动化与真实 GUI 操作没有混淆
-   [ ] 仿真和真机结果分开
-   [ ] 关键验收标准有证据
-   [ ] 变更影响与回归测试已检查
-   [ ] 已知限制写入交付说明
